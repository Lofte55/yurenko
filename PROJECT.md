# YURENKO — описание проекта

Сайт компании **YURENKO** (ритейл-дизайн торговых центров, основатель — Алёна Юренко).
Заменяет старый одностраничник на Tilda `wndw.tilda.ws`.

---

## 1. Что это за сайт

Многостраничный статический сайт без базы данных и без фреймворков: чистый HTML, CSS и
ванильный JavaScript. Собирается маленьким Node-скриптом, деплоится на Vercel.

**Кому он отвечает и на какие вопросы:**

## 2. Дизайн-система

Референс — writer.com, адаптированный под ритейл-дизайн. Светлый «редакционный» холст,
пилюли вместо прямоугольных кнопок, один акцентный цвет, чередование светлых и тёмных секций.

**Цвет.** Акцент — Tiffany `#0abab5`, глубокий вариант `#0b807c`. Тёмные секции — `#161a19`.
Больше акцентных цветов в систему не вводим: если нужно выделить что-то ещё, используем
вес шрифта и воздух, а не новый цвет.

**Шрифт.** Только Manrope, 400–800, самохостится из `assets/fonts/` (не зависим от
Google Fonts — важно для доступности сайта в России). Заголовки с отрицательным трекингом,
надзаголовки (`.eyebrow`) — 12px, uppercase, широкий трекинг.

**Форма.** Кнопки и поля ввода — радиус 60–72px (пилюли). Карточки и картинки — 12px.
Больших теней нет нигде, кроме карточек первого экрана, которые лежат на цветном полотне.

**Анимации.** Пословное появление заголовка первого экрана, scroll-reveal секций
(`data-reveal` + IntersectionObserver), счётчики (`data-count`), бегущая строка фактов,
аккордеоны на CSS grid. Всё уважает `prefers-reduced-motion`.

## 3. Как устроена сборка

Каждая страница = один файл в `pages/`, состоящий из META-блока и разметки `<main>`.
Скрипт `tools/build.mjs` подставляет общие шапку, подвал и `<head>`, копирует статику
и складывает готовый сайт в папку **`public/`** — именно её публикует Vercel.

```
pages/services-training.html   →   public/services/training/index.html
assets/                        →   public/assets/
```

Папка `public/` пересоздаётся при каждой сборке с нуля и не хранится в git.

Запуск сборки:

```bash
npm run build
```

Скрипт заодно генерирует `sitemap.xml` и `robots.txt` из списка маршрутов.

### META-блок

Первые строки файла в `pages/`:

```
<!--META
route: /services/training/
title: Заголовок вкладки и выдачи
description: Описание для поиска и соцсетей
ogtitle: Необязательно — заголовок для соцсетей, если он отличается
scripts: /assets/js/generator.js
jsonld: {"@context":"https://schema.org", ...}
-->
```

Обязательны только `route`, `title` и `description`.

## 4. Что можно трогать, а что нельзя

### ✅ Редактируем свободно

| Файл или папка | Что здесь |
|---|---|
| `pages/*.html` | **Весь текст сайта.** Правки контента делаются только здесь |
| `partials/header.html` | Шапка и мобильное меню — общие для всех страниц |
| `partials/footer.html` | Подвал — общий для всех страниц |
| `partials/head.html` | Подключение шрифтов и стилей |
| `assets/img/` | Картинки |
| `assets/css/base.css` | Дизайн-система: цвета, типографика, компоненты |
| `assets/css/generator.css` | Стили визарда ТЗ |
| `assets/js/app.js` | Навигация, анимации, формы, кастомные селекты |
| `assets/js/generator.js` | Логика генератора ТЗ: сферы, вопросы, сборка документа |
| `api/submit.js` | Приём заявок |
| `tools/make-og.mjs` | Тексты карточек-превью для соцсетей |

### ⛔ Не трогаем — перезапишется при сборке

| Файл | Почему |
|---|---|
| Вся папка `public/` | Результат сборки. Удаляется и создаётся заново при каждом `npm run build`, в git не хранится |

**Правило простое:** если правку внесли внутри `public/` — она исчезнет при следующей
сборке. Ищите исходник в `pages/`, `partials/` или `assets/`.

### Как добавить новую страницу

1. Создайте `pages/новое-имя.html` с META-блоком и разметкой `<main>`.
2. Пропишите `route: /новый-маршрут/`.
3. Добавьте ссылку в `partials/header.html` и `partials/footer.html`, если страница нужна в меню.
4. Запустите `npm run build`.

## 5. Генератор ТЗ

Главный инструмент привлечения заявок. Живёт на `/generator/`, логика — в
`assets/js/generator.js`.

**Как работает:** 7 шагов — сфера, объект, цели, состав работ, условия, материалы, контакты.
Набор вопросов на шагах 3 и 4 зависит от выбранной сферы. Черновик сохраняется в браузере
посетителя (`localStorage`, ключ `yurenko_tz_v1`), поэтому закрытая вкладка не теряет ответы.

**Шесть сфер** (объект `SCOPES` в начале файла):
`mall` — дизайн-стандарты ТЦ, `store` — магазин, `island` — остров и киоск,
`food` — фуд-корт, `windows` — витрины, `training` — обучение.

**Как отредактировать вопросы:** откройте `SCOPES` и правьте массивы `works` (состав работ)
и `goals` (цели) у нужной сферы. Заголовок, описание и цена — поля `title`, `lead`, `price`.

**Как добавить сферу:** добавьте ключ в `SCOPES` со всеми полями по образцу существующих.
Карточка выбора появится автоматически.

**Ссылка с предвыбранной сферой:** `/generator/?scope=store` — открывает визард сразу
на втором шаге с выбранным направлением. Такие ссылки стоят на страницах услуг.

**Что получает посетитель:** структурированный документ с разделами резюме, цели,
объём работ, вне объёма, условия, исходные материалы, этапы, критерии приёмки, ориентир
по стоимости. Его можно скопировать, скачать `.md` или распечатать в PDF. Копия уходит
на почту посетителю и вам.

## 6. SEO и превью ссылок

### Что настроено

- **Уникальные title и description** на каждой странице: title до 60 символов,
  description 120–160 — в этих пределах поисковик показывает текст целиком, не обрезая.
- **OG-изображение под каждую страницу** — брендированная карточка 1200×630 в
  `assets/img/og/`. Именно она показывается, когда ссылку отправляют в Telegram,
  WhatsApp, ВКонтакте или Slack.
- **Twitter Card** типа `summary_large_image` — крупное превью вместо иконки.
- **Микроразметка Schema.org**: `ProfessionalService` с каталогом услуг и ценами на
  главной, `BreadcrumbList` на всех внутренних страницах, `FAQPage` на страницах
  с блоком вопросов (даёт раскрывающийся список прямо в выдаче), `Person` на «О нас».
- **robots.txt** с отдельной секцией для Яндекса и `Clean-param` — метки UTM,
  `yclid`, `gclid` и `fbclid` не плодят дубли страниц в индексе.
- **sitemap.xml** с `lastmod`, `changefreq` и приоритетами. Страница 404 в него не попадает.
- **Страница 404** с навигацией по разделам. Vercel отдаёт её автоматически.
- `canonical` на каждой странице, `max-image-preview:large` для крупных картинок в выдаче.

### Как обновить превью ссылки

Тексты карточек лежат в массиве `CARDS` в `tools/make-og.mjs`. После правки:

```bash
npm run dev     # в одном терминале — нужен работающий сервер на :3140
npm run og      # в другом — перерисует PNG в assets/img/og/
```

Тег `<em>` внутри `title` красит слово акцентом, как на сайте.
Флаг `portrait: 1` добавляет фото Алёны справа.

### Привязка картинки к странице

В META-блоке страницы: `og: mall-standards` — берёт `assets/img/og/mall-standards.png`.
Если поле не указано, подставляется `home.png`.

### Важно про домен

Адреса OG-картинок абсолютные и указывают на `https://yurenko.ru`. Пока боевой домен
не подключён, превью на служебном `*.vercel.app` работать не будет — это нормально.
После подключения домена прогоните ссылки через отладчики:
[Telegram](https://t.me/WebpageBot), [ВКонтакте](https://vk.com/dev/pages.clearCache),
[Facebook](https://developers.facebook.com/tools/debug/). Они сбрасывают кеш превью.

### Яндекс.Метрика

Счётчик `112141491` подключён в `tools/build.mjs` (константа `METRIKA_ID`) с вебвизором,
картой кликов и отслеживанием внешних ссылок. На `localhost` не срабатывает, чтобы
разработка не попадала в статистику.

После деплоя подтвердите права на сайт в Яндекс.Вебмастере и Google Search Console
и загрузите туда `sitemap.xml`.

### Кнопка WhatsApp и цель в Метрике

Плавающая кнопка в левом нижнем углу — в `partials/footer.html` (`.wa-fab`), поэтому
видна на каждой странице. Ведёт на `https://wa.me/77051399058` с приветственным
текстом в чат. Номер и текст сообщения меняются прямо в `href` этой кнопки.

Клик по кнопке отправляет в Метрику цель **`whatsapp_click`** (`assets/js/app.js`,
обработчик `[data-wa-track]`). В интерфейсе Метрики создайте цель того же типа —
«JavaScript-событие» с идентификатором `whatsapp_click` — тогда клики попадут
в отчёты по конверсиям и в «Целевые звонки».

## 7. Приём заявок

Все формы на сайте отправляют POST на `/api/submit`. Обработчик — `api/submit.js`,
серверless-функция Vercel. Она пишет в Telegram и отправляет письма через Resend.
Длинное ТЗ уходит в Telegram файлом, потому что у сообщений там лимит 4096 символов.

**Переменные окружения** (Vercel → Settings → Environment Variables):

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | для Telegram | Токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | для Telegram | ID чата или канала, куда падают заявки |
| `RESEND_API_KEY` | для почты | Ключ resend.com |
| `MAIL_FROM` | для почты | Отправитель, домен должен быть подтверждён в Resend |
| `MAIL_TO` | для почты | Куда дублировать заявки, можно несколько через запятую |
| `ALLOWED_ORIGIN` | желательно | `https://yurenko.ru` — ограничивает CORS |

Достаточно настроить один канал: только Telegram или только почту. **Если не настроен
ни один — формы отвечают «отправлено», но заявка никуда не уходит.** Настройте до запуска.

## 8. Локальная разработка

```bash
npm run dev
```

Собирает сайт и поднимает статику из `public/` на `http://localhost:3140/`.
Только сборка — `npm run build`. Формы локально работать не будут: `/api/submit`
существует только на Vercel. Чтобы проверить и API, поставьте Vercel CLI и запустите
`vercel dev`.

## 9. Деплой на Vercel

1. Импортируйте репозиторий `Lofte55/yurenko` в Vercel.
2. Framework Preset — **Other**. Build Command и Output Directory подставятся из
   `vercel.json` — `npm run build` и `public`, менять в интерфейсе ничего не нужно.
3. Добавьте переменные окружения из раздела 7.
4. Подключите домен.

`vercel.json` задаёт: команду сборки, выходную папку `public`, чистые URL, слэш в конце
и годовое кеширование статики. Функции из `api/` Vercel подхватывает из корня репозитория,
копировать их в `public/` не нужно и нельзя.
